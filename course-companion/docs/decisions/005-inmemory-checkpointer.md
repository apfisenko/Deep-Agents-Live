# ADR 005: InMemorySaver для v1 CLI

**Статус:** Принято  
**Дата:** 2026-08-02  
**Автор:** Course Companion Team

---

## Контекст

LangGraph требует checkpointer для многоходового диалога (хранение `thread_id` → state). Для v1 необходимо выбрать реализацию: хранить историю в памяти или в persistent-хранилище.

## Решение

`InMemorySaver` из `langgraph.checkpoint.memory` — хранение в памяти процесса.

```python
checkpointer = InMemorySaver()
return builder.compile(checkpointer=checkpointer)
```

## Альтернативы

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **InMemorySaver (выбрано)** | Ноль зависимостей; тривиальный тест; достаточен для CLI | История теряется при перезапуске |
| PostgresSaver | Сессии переживают перезапуск | Требует PostgreSQL, миграции, async-драйвер |
| SQLiteSaver | Файловый persistent; без внешних сервисов | Дополнительная зависимость; усложняет тесты |
| Redis checkpoint | Быстро; горизонтально масштабируется | Избыточно для CLI |

## Обоснование

Course Companion — CLI-инструмент для одного студента. Каждый запуск `uv run companion` — новая сессия. Требование «сессия переживает перезапуск» не заявлено в v1.

`InMemorySaver`:
- Не требует инфраструктуры — `uv sync` достаточно для запуска.
- Тесты изолированы — нет состояния между тест-кейсами.
- Легко заменить на persistent checkpointer: один `import`, один параметр в `build_graph()`.

Persistent-хранилище зафиксировано в backlog (roadmap, раздел «Вне v1»).

## Последствия

- История диалога живёт в памяти процесса — перезапуск = новая сессия.
- Многоходовой диалог работает корректно в рамках одного запуска.
- Замена на `AsyncPostgresSaver` потребует изменения только в `build_graph()`.
- Тесты используют тот же `InMemorySaver` — нет разрыва между test и prod окружением.
