# ADR 004: `review` не входит в Literal Router

**Статус:** Принято  
**Дата:** 2026-08-02  
**Автор:** Course Companion Team

---

## Контекст

Router классифицирует интент студента в одно из состояний: `qa`, `homework`, `stay`. Режим `review` существует в системе, но не является опцией Router. Это требует явного объяснения.

## Решение

`RouteDecision = Literal["qa", "homework", "stay"]` — `review` намеренно отсутствует.

```python
# intent.py
RouteDecision = Literal["qa", "homework", "stay"]
# "review" намеренно отсутствует — это состояние флоу, не интент пользователя.
```

## Обоснование

`review` — **состояние пайплайна**, а не **интент пользователя**. Студент не говорит «хочу перейти в режим разбора фидбека» — он сдаёт ДЗ, и система автоматически переходит в `review` через тул `complete_homework`. Это внутренний переход флоу, а не намерение.

Если `review` добавить в Router:
- LLM может ошибочно классифицировать любой вопрос как `review` (например, «разбери мой код» → `review`).
- Router потерял бы семантическую чёткость: `qa`/`homework` — это то, что хочет студент; `review` — это то, что сделала система.
- Студент в режиме `review` всегда общается с тем же Companion; Router продолжает классифицировать дальнейшие ходы как `qa`, `homework` или `stay`.

## Последствия

- Router всегда возвращает одно из трёх значений: `qa`, `homework`, `stay`.
- Переход в `review` возможен только через `complete_homework` (внутренний тул).
- Выход из `review` — через `return_to_qa` или `resubmit_homework`.
- Если студент в `review` говорит что-то не связанное с фидбеком, Router ответит `stay`, и Companion продолжит разбор в review-контексте.
